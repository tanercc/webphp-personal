# CMS reference repository and Personal example

- This repository is a standalone PHP 8.4 + SQLite portfolio demo. Do not modify other projects or copy their content, configuration, uploads, or users.
- For reuse, read `docs/mimari.md` and `docs/yeni-site.md` first. Personal remains the working example here. Use `tools/create-site.php` for a new project; do not copy the runtime database, sessions, uploads, secrets, or demo seed. New projects receive the guide in `starter/AGENTS.md`.
- Run `git status --short` first. This directory is the workspace root. The live database is `storage/personal.sqlite`; sessions and logs are excluded from Git.
- Composer/npm is not required. Preserve the existing panel and official packages. Do not patch vendor sources manually or replace the editor/file manager.
- `config/site.php` defines the installation name, profile, database path, and session settings. Preserve the reference demo's cookie name and database path. `database/seed-base.sql` contains neutral metadata and a home page, with no users. The starter installer creates an administrator with a password supplied through the environment and stores only its hash.
- `database/schema.sql` contains CREATE statements; `database/seed.sql` contains fictional demo data only. Update the schema and relevant seed together when changing the data model. Installation must not delete or overwrite an existing database. Never import a seed into a live database.
- The PDO SQLite adapter is in `panel/include/sqlite.php`. Keep values parameterized and preserve identifier, table, and field allowlists. The adapter covers only the query contract currently used by the panel.
- Preserve the HTTP API's `data/itemsCount`, string IDs, soft deletion, translations, and role/action/field/CSRF contracts. Forms use column types and defaults returned by SQLite `PRAGMA table_info`.
- The site is built manually with PHP in `templates/pages` and `templates/partials`; do not introduce a theme engine. Installation-specific field labels belong in `config/panel-fields.php`. Render rich HTML only with `panelRichHtml()`; use `panelHtml()` / `e()` for other HTML contexts.
- The official theme files `css/styles.css`, `js/scripts.js`, profile image, and Bootstrap/font assets are unchanged. Sources and hashes are recorded in `docs/theme-*.json`. Custom CSS belongs in `css/site.css`. `assetAttributes`/`scriptAttributes` derive SRI and content versions from the same file bytes; do not remove this behavior.
- The panel uses the CKEditor 4.22.1 standard package, not supported LTS. Keep `fullPage:false`, `disallowedContent:'script;style'`, and `versionCheck:false`. Do not distribute/enable samples or GeSHi. Enabling these features requires a new security assessment.
- Preserve the file manager's shared authentication/CSRF checks and record scope through `RF.subfolder`. A missing folder must not fall back to the shared root. Remote URL loading, archive extraction, quick upload, and active-document writes remain disabled. Preserve SRI values for the local jQuery/UI files.
- The demo accepts only a genuine loopback `REMOTE_ADDR`. Local login uses hashed passwords, CSRF, rate limiting, and session ID rotation without CAPTCHA. Do not silently remove the loopback restriction to publish the site; assess production deployment separately. Never add an authentication-bypass endpoint for tests or users.
- The contact form saves messages locally and sends no email. `datas` type 6 is the inbox; messages are rendered as plain text. The IP limit is 5 messages per 15 minutes.
- `router.php` and Apache `.htaccess` protect config/database/storage/tools/templates/tests, starter source files, and vendor examples from HTTP access. The PHP development server requires the router. Nginx needs equivalent rules.
- For PHP changes, lint the affected files and run `python tests/http-workflows.py` and `php tools/verify.php`. Write tests must use disposable SQLite databases. Do not add unnecessary one-off test files.
- The public demo is Turkish by default. English translation records remain available in the panel; there is no separate public-language route. Generic CMS template choices do not automatically add Personal layouts; see the README content mapping.
